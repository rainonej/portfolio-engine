# Portfolio site setup prompt template

Copy this into an agent when creating a new downstream site with `@portfolio-engine/editorial-theme`.

**This file is a template only.** Do not treat any example words below as site copy, brand voice, or recommended positioning.

For technical steps, follow:
https://github.com/rainonej/portfolio-engine/blob/main/docs/downstream/new-site-setup.md

For the full phased workflow (admin tools, git branches, Vercel), use:
https://github.com/rainonej/portfolio-engine/blob/main/docs/downstream/setup-with-claude.md

## Agent instructions

You are helping create a personal portfolio site using `@portfolio-engine/editorial-theme`.

Before touching files, collect the following from the site owner in one message (or confirm what you can infer from documents they already provided):

- Name (as it should appear on the site)
- Role line (what they do)
- Tagline (one short line)
- One-sentence description (work and audience)
- Location (city and country)
- Tone (how they write)
- Audience (who reads the site)
- Pages to include (Work, Writing, About, Contact, Résumé, etc.)
- Repository name
- Resume or profile source, if available
- Social links and optional booking/scheduling URL
- Any terms, claims, or positioning to avoid

After collecting answers:

1. Scaffold the Astro project and install `@portfolio-engine/editorial-theme` (and optional `@portfolio-engine/admin-tools` if requested).
2. Create `src/config`, `src/content`, `src/context`, and wire overrides only as needed.
3. Use **only** the site owner?s answers and uploaded/source materials for **runtime copy**. Do not copy brand language from this template, from other downstream sites, or from old transcripts.
4. Keep a short friction log if something in setup is unclear (e.g. `src/docs/setup-feedback.md`).
5. Commit the initial site and summarize what was created.
6. Give exact deployment steps (e.g. Vercel import, Node version, env vars).

---

## Content source-of-truth rule

The downstream user?s answers and their `src/config`, `src/content`, `src/context`, `src/pages-local`, and `src/overrides` are the source of truth.

Example names, roles, taglines, and audiences in upstream docs are **placeholders only**.
